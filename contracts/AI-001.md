## 兼容和启用

**2026-11-13 原生 worker 开发扩展，Integration/Core 复核：**`ai_backend` 可用以下互斥配置选择受信任的本机原生程序，所有路径仍须为绝对路径；旧 Python 配置不变，混用、缺字段或相对路径拒绝。只有明确 `development_root` 的受控开发路径可以执行，公开 capability 仍为不可用。八个 C ABI 和旧 JSON 保持；内部公开 Rust 类型 `AiBackendConfig` 的字段已变为 `AiWorker` 枚举，直接使用旧字段或结构体字面量的 Rust 源码需要迁移。

```json
{"native_worker":"/EXAMPLE/media-ai-worker","native_graphs":"/EXAMPLE/graphs","native_runtime":"/EXAMPLE/libonnxruntime.dylib","model":"/EXAMPLE/model.onnx","timeout_ms":600000,"development_root":"/EXAMPLE/private-root"}
```

Core 用参数数组启动 `native_worker --graphs GRAPH_DIR --runtime RUNTIME --model MODEL --input INPUT --staging STAGING`，无 Python 参与；复用原有结果协议、资源预算、队列、取消和双输出提交。worker 对固定原模型及八个固定子图检查摘要并使用校验后的图字节。该配置只接受可信本机开发组件，Core 的路径/metadata 检查不构成发行二进制、运行时或许可认证；具体验证范围见 [ADR-0015](../docs/adr/0015-native-ai-worker-proposal.md)。

保留现有八个 C ABI 签名、`ms_buffer` 布局与分配/释放方、同一 engine 调用者串行化、panic 捕获隔离、错误码和 schema_version=0。旧输入、默认 mock 与 CORE-002/003/004 的旧 JSON/语义不变。新的配置只在显式可选 `media_backend.ai_backend` 中出现；缺失时不创建 AI worker、不读取模型、不下载或假报可用。旧 Core 拒绝新字段或 operation，调用方不能静默删字段重试。旧引擎不可提交 AI；未被明确接收的平台不可声明支持。

提案配置（示例路径不可当可用工具）：

```json
{"schema_version":0,"media_backend":{"ffmpeg":"/EXAMPLE/ffmpeg","ffprobe":"/EXAMPLE/ffprobe","core003_enabled":true,"core004_enabled":true,"ai_backend":{"python":"/EXAMPLE/python","worker":"/EXAMPLE/stream_worker_v1.py","model":"/EXAMPLE/model.onnx","timeout_ms":600000}}}
```

字段仅为绝对本地路径及正整数超时（1..7,200,000 毫秒）；拒绝空字符串、NUL、未知字段/类型、不支持配置组合。为共用现有队列和重任务 permit，AI 要求显式 `core003_enabled`、`core004_enabled` 为 true；不得靠跨 engine 启多个重任务。`ai_backend` 不接受自由 argv、shell、网络 URL、用户指定校验散列或任意模型；初版唯一模型 ID 与 SHA-256 固定为 `umx_hq_vocals_onnx_v1` / `f27742bb52b24cb039614dc76d0764e279df3eb2a9d6daa82c6daee3369ec747`。模型必须对**将传给运行时的实际字节**验证完整哈希。解释器/worker/依赖固定版本、来源、二进制身份、加载环境及被替换竞态须经 Integration 审核，不能用调用方自报哈希证明可信；在这些保证及实际功能测试未完成前只允许受信开发环境，公开 capability 不得可用。权限和发行方案另审，顶层 MIT 不覆盖每个轮子中的原生库。

## 提交与首个有界子集

`ms_submit_job` 输入 UTF-8 JSON：

```json
{"schema_version":0,"operation":"ai_separate","source":{"uri":"file:///EXAMPLE/input.wav"},"destination":{"uri":"file:///EXAMPLE/NEW_DIRECTORY"},"model_id":"umx_hq_vocals_onnx_v1"}
```

`source` 为现有契约规定的本地 file URI；`destination` 是**尚不存在的结果目录**，其父目录必须存在、可授权且与 staging 同卷。解析与路径检验复用 Core 唯一语义；不允许网络 URI、NUL、空叶名、源或目标别名、未知字段/模型。目标已有任何对象（包括空目录、文件、符号链接）拒绝且保持原样；不能自动改名或覆写。源文件只读，授权和文件/父目录身份须覆盖完整后台作业；源变化、目录替换、授权丢失及目标竞争均安全失败。

**历史首个开发子集**仅接受精确 44,100 Hz 双声道 IEEE float WAV，2,049..26,460,000 个 PCM 帧，所有采样有限、峰值≤1（峰值限制与格式扩展由本文后续修订取代），输入应完整可解码；不接受小于2049帧、其他率/声道/编码，不能静默上混或重采样。此限制仅供第一轮 Core/worker 开发和失败测试，不改变产品目标：AC19 仍需 1 秒/30 秒/10 分钟、44.1/48 kHz、mono/stereo、WAV/FLAC/MP3/M4A 与静音、输入解码与采样映射，最终输出 N=round(源采样数×44100/源采样率)。此有限子集不可标记首版或 AC19 通过。对未知或不支持的输入返回可解释 `UNSUPPORTED_FORMAT` 或 `INVALID_INPUT`，不存在输出且源不变。

当 Core 已实现并通过上述安全/接收条件时，作业采用 CORE-004 队列的接收/ID/32非终态/100历史/排序/取消/重试语义；批量/重试接纳 AI 前必须冻结其目标目录身份、预算与幂等细则并增加对等契约测试。现在**不假定**现有 batch 接受 AI：可以先做单作业受控开发路径，batch/retry 未实现时应明确拒绝，不能循环模拟批次成功。提交同步解析/预检失败无 job ID、无目标；有效接收才分配真实 job ID 并进入既有队列。公共消息结构、错误与 ID 以 CORE-004 为基础，`progress` 未知为 null，不伪造百分比，不泄露绝对路径或原始 stderr。

### 错误映射和无 ghost job

本段为开发基线；目前 Core 只实现严格解析及部分源缺失/目标已存在的只读拒绝，有效 AI 请求仍为 UNSUPPORTED、capability=false；其余错误映射须按具体阶段实测，不能声称本段已实现。语法/结构/未知字段/无效本地 URI 或路径/未知模型 ID 同步返回 `MS_E_INVALID_ARGUMENT (-1)` 且 out buffer 为空；非法 UTF-8 为 -3、非 0 schema 为 -4、JSON 语法或非对象为 -5、长度超过上限为 -9。缺少显式 AI 配置的引擎，对 schema 有效、`operation` 为 `ai_separate` 的对象优先返回 `MS_E_UNSUPPORTED_OPERATION (-8)`，即使该 AI 请求的其他字段不完整或无效，也不得访问源/目标/模型；这保留旧引擎语义。只有明确启用后才校验 AI 专属字段。新配置错误在 engine_create 同步拒绝，不创建 engine。

AI 已显式启用且 Core 队列解析成功后，已知业务预检错误沿 CORE-004 的 `MS_OK` 控制响应：`{"schema_version":0,"operation":"ai_separate","accepted":false,"errors":[{"index":0,"code":"INVALID_INPUT","message":"..."}]}`；不返回 job ID、不创建最终目标。源缺失、非普通或空文件为 `INVALID_INPUT`；已有目标为 `OUTPUT_EXISTS`；worker/解释器/模型缺失为 `DEPENDENCY_MISSING`；存在但固定模型哈希不符为 `MODEL_INVALID`；队列容量/资源预算不足为 `RESOURCE_LIMIT`；清理不能确认则 `CLEANUP_FAILED` 并隔离。错误消息为固定文本，不回显原始路径。预检与实际执行间的来源变更和目标竞争仍可能发生，应在 job snapshot 以同类结构化错误报告 failed；`accepted:true` 只代表入队而不保证成功。非法配置、模型不可用及已知预检失败不得额外消费 job ID、产生半组、覆盖源或目标。

## worker 边界与输出

2026-11-14 原生失败分类补充（ADR-0018，Integration 已独立静态审核，动态证据另记）：native worker 在实际 IO 错误链含 ENOSPC=28 时，可返回单行 `{"schema_version":1,"error":"OUT_OF_DISK"}` 和专用退出状态73。Core 只在 native 调用点同时验证状态及完整固定 JSON 后映射公开 `OUT_OF_DISK`；其他状态/响应仍按原失败路径，Python及其他工具的退出状态不继承此解释。原有超时/取消/回收/清理失败优先级不变，八函数 ABI、成功响应及双 stem 发布要求不变。具体实测与审核状态见 ADR-0018 及 QA-002 证据，不以此文字声明实现已通过。

Core 以参数数组启动受控的单个独立 worker：旧 Python 分支使用 `python -I stream_worker_v1.py --model ABS --input ABS --staging ABS`，原生分支使用上方原生配置所列参数。必须采用明确受控的加载环境，限定输出/执行时间和资源；worker 不得自动联网、下载或开启子进程，但声明本身不构成 OS 沙盒。worker 可以在唯一私有 staging 内排他创建 `encoded.f32`、`layer0.f32`–`layer2.f32` 等受限中间文件以及两个固定 stem；当前 Python 实现将四个 mmap 文件在打开后 unlink，原生实现使用打开后 unlink 的临时文件，空间由 fd 持有，目录枚举和 du 不能观察它们。scratch 不可出现在最终结果目录，只有回收进程/关闭所有 mmap、fd 后才能确认已释放；未确认时隔离并保留资源所有权。设 T=floor(N/1024)+1，应按实际实现保守预留不少于四个 T×512×4 字节特征、两条 N×2×4 字节输出和容器开销；若复制规范化输入，还需额外 N×2×4 字节及容器开销。还需预留余量并检查卷剩余空间，无法建立预算时拒绝；运行期监测不等于不可超出的硬磁盘配额。模型是固定 UMX-HQ ONNX，窗口 n_fft=4096、hop=1024、periodic Hann、全局 center reflect，仅完整帧，按层分方向传递完整 LSTM hidden/cell，不用有限上下文分块近似或静默替代算法。声乐预测为 `vocals.wav`，`accompaniment.wav` 为相同采样点的输入减声乐；两者以 float32 WAV 输出，N 和输入一致。worker 输入必须完整验证，不能只看扩展名或头部；bad/非有限/越限拒绝，静音不除零。

worker 成功 stdout 是**单行** JSON：`schema_version:1`、内部固定 `model_id:"open-unmix-umxhq-vocals-onnx-e06097d3"`、`frames`、`sample_rate:44100`、`channels:2` 和 `outputs:["vocals.wav","accompaniment.wav"]`；Core 必须显式验证内部 ID 与公开 `umx_hq_vocals_onnx_v1` 的固定映射，不能把两种字符串当作相同。失败返回非零与固定错误类别，不回显源路径、目录或堆栈，stdout/stderr 均有界、不得死锁。进程退出0/文件存在/worker自报不等于成功。Core 必须在 worker 及后代停止、写入句柄关闭后，独立检测两个输出都是其持有 staging 内无链接的预期普通文件、全段解码通过、采样率/声道/编码/精确帧数、无NaN/Inf、没有不明文件和未清理 scratch；验证源未变、预算及目录身份仍有效。结果至少包含 operation/state、两个固定逻辑名、帧数/采样率/通道、model ID、输入/输出时间映射；不要回显敏感绝对路径至普通日志。

## 安全提交、取消和异常

目标父目录的授权与受控 fd 从创建 staging 到确认终态保持，staging 同父目录私有、独占创建。成功提交的线性化点是 `renameatx_np(parentfd, stage_leaf, parentfd, destination_leaf, RENAME_EXCL)` 或经独立审定的等效单次无覆盖目录操作，两个 output 同时作为一个目录发布。路径名必须单组件且 NUL 等被拒绝，目录句柄持续有效；`EEXIST` 不覆盖目标，`ENOTSUP`/`EXDEV`/权限/无法确认时拒绝，不退化为普通 rename 或逐文件复制。对 Core 已创建对象的清理必须明确身份，不能单凭 `stat` 后 `unlink` 假称原子或删除不明对象。父目录可被同 UID 并发修改时的 staging 置换/源身份竞态尚未解决，必须定义受信父目录/OS 隔离的有效边界并实测；保证不了时拒绝提交，不因 0700 或 NOFOLLOW 自动视为安全。

取消 queued 阻止启动并经确认终态；running 进入 cancelling，先终止并确认回收实际 worker **及后代**、关闭管道和写入句柄，再清理由该任务持有且身份可确认的 staging，完成后才 cancelled；重复取消幂等。超时、worker 非零/异常退出、模型错误、无效响应/输出、第二 stem 写入失败、磁盘不足或目标竞争均不得发布半组；先停止所有写入再清理。清理或进程回收未能确认必须 `CLEANUP_FAILED` 并保留 ownership/quarantine，禁止使用已有资源重复启动或假报 cancelled/成功。实现者要明确的错误码不得回显路径/密钥。`destroy` 对非终态保持 BUSY、等待取消和确认清理，与原 ABI 所有权规则一致。

取消与提交共用单一状态锁/原子判定：提交前已生效取消则不能发布，提交点已成功后并发取消不能删除目录或把成功回报为取消。若进程在提交成功后、回执前 crash，重启时不得仅凭目标存在就认定属本任务或自动删除；交易身份/恢复协议需单独冻结并验证，暂且返回不确定/人工恢复且不声明重启自动恢复。原子可见性不保证断电持久性；只有经实测的持久化协议可声明。

## 受控队列开发路径（2026-11-10 Integration/Core 修订；非产品接收）

为使真实 worker 能在共享队列进行受控开发验证，`media_backend.ai_backend` 增加可选 `development_root`：绝对路径、有效目录，供唯一调用方在本机 macOS arm64 使用。字段缺省时沿用前述严格解析和只读预检：已知源/目标业务错误可按既有映射拒绝，其他合法 AI 请求返回 `MS_E_UNSUPPORTED_OPERATION (-8)`；不分配 AI job、不启动 worker、不创建目标。不得从未启用配置的旧请求中推断 root；未知/相对/空/含 NUL 的配置拒绝。

当明确提供 root 时，受控路径仅接受当前有效 UID 拥有且权限位为 0700 的本地目录；root 自身及使用到的路径分量不跟随符号链接。`source` 与 `destination` 均必须是该 root 下**一个**合法的直接叶组件，不能靠字符串前缀判断，也不能含 `.`、`..`、分隔符或 NUL；源是非空、单硬链接的普通文件，最终目标不存在（包括悬空链接），stage 在同一个已打开的 root 目录 fd 内私有排他创建。root、源和 stage 需持有可验证的 fd/设备与 inode；提交前后检查可见身份，授权/身份变化、路径置换、冲突或无法确认时禁止宣称成功，保留 owner 并 quarantine，不删除未知对象。结果在 root 下的一个新目录，包含两个固定 stem。已获得的 fd 不允许被 UI 提前关闭；源始终只读。实际卷对 `RENAME_EXCL` 不支持时失败，不退化到覆盖式操作。

该路径为**受信开发环境**：调用方明确负责提供受控解释器/虚拟环境、worker 文件和模型来源，以及没有同 UID 恶意或非协作进程同时修改 root、脚本、依赖或模型的命名空间。`0700`、最终分量 `O_NOFOLLOW` 和持有 fd 均不能证明抵御同 UID 进程、ACL、动态库劫持或在 `fstat` 与按名 rename/unlink 之间的竞争；不得将此假设描述为通用用户目录安全，更不能据此开放普通 UI、自动下载或发布。检查到路径、源或目录身份不一致、回收/清理不确定时 fail closed，保留受影响 owner 和重资源许可，不得自动重试或误报 cancelled/succeeded。根目录 ACL、父目录及重启后的恢复/隔离仍需平台专项验证。此开发限定不是 AC19 正式支持范围，不改变 44.1/48k、格式/声道转换、长任务、权限、听感或其他平台的必选验收。

开发 worker 与模型的精确来源/哈希及实际依赖由 Integration 与 Core 固定复核；旧 Python 分支以受控解释器的 `-I` 模式运行固定脚本，原生分支按上文固定 argv 启动；两者均清空环境并设置明确必要白名单，模型对交给运行时的**实际字节**校验固定 SHA。解释器、framework、已安装包与原生库仍受明确本机可信环境前提约束，`-I` 并不校验 wheel 或阻断 `.pth`/动态库替换。真实开发作业进入 CORE-004 单一队列并共享进程级 heavy permit；同一 job owner 持有 worker/进程组、stage/root/源身份及空间 reservation，进程树未确认回收或 cleanup 不确定必须统一 quarantine，不能因各组件自己的标志独立而漏隔离。worker 开始后只在其确认回收并完成独立音频验证后，才在队列状态锁内对取消与目录单次 no-clobber 发布进行线性化；完成 rename 后取消不回滚成功。阶段中的 stdout/stderr 有界但可能含敏感数据，不得直接回显。未知进度仍是 null。

公开 `features.ai_separation.available` 在实现、安全复审、独立 QA 及分发前置审查未完成时**保持 false**。在此显式开发配置下允许对有效测试素材创建实际 AI job 以供 QA 验证，不代表普通客户端功能已接收；客户端不可依据未接收扩展推断平台普遍支持。开发请求的成功、取消和异常结果须以实际 job 状态和证据为准。macOS arm64 外、自然长歌曲、双人听评及发行渠道不能由开发路径自动继承；沙盒和普通用户目标目录的定向验证及剩余边界见 MAC-004 QA。

## 受控开发格式规范化（2026-11-10 Integration/Core 联合决策）

本节定义后续实装与验收要求，不等于支持已实现：只在原 `development_root` 明确启用时扩展输入，目标矩阵为音频-only WAV（PCM16/24/float32）、FLAC、MP3、M4A/AAC-LC，44.1/48 kHz、mono/stereo、单音频流；具体组合只有真实执行通过后才可宣称支持。读取实际容器与流信息，限定协议、封装、编码、采样率和布局；多轨、视频或附件等非声明流、明确非 mono/stereo 的布局、损坏/非有限/超限、不可确定实际解码结果一律明确拒绝，不静默选轨、混音或联网。白名单音频编码仅在布局缺省时约定 1 声道为 mono、2 声道为 stereo；WAVE extensible 仅接受 mono mask 0/4 和 stereo mask 0/3，0 按上述缺省规则处理，其他 mask 拒绝。单声道复制到左右声道；立体声保持顺序。FFmpeg/ffprobe 采用配置的绝对路径及固定参数数组、受控进程和有限输出，不插入 shell；其实际构建的使用和分发许可分别审查。

规范化前对音频按源采样率完整解码，依据实际有效解码帧数计算 `N=(source_frames*44100+source_rate/2)/source_rate`（正整数最近舍入，半数向上），以此作为两 stem 的 44.1 kHz 帧数目标，不能用容器估计时长代替。固定转换命令输出与 N 相差一帧时，允许在**末尾**裁剪多余帧或补一个零帧，并在测试证据中记录修正；差距超过一帧拒绝，不能通过相关峰任意平移。编码延迟、填充与其他解码器的普遍适用性必须单独验证；仅可对实际执行的组合报告。源文件始终只读且任务前后检查身份；不得将源用作暂存。原输入及标准化后的 WAV 均须完整扫描有限值，受控开发路径的工程峰值上限为绝对值 2.0；允许合法的超过满幅浮点值，超过 2.0 或非有限明确拒绝，不静默削波或归一化。2.0 只是数值边界，并不证明该范围内所有输入的听感；修改 worker 时必须更新固定 worker 源码散列，并独立测试超过 1.0 的输入、接近和超过 2.0 的边界、输出有限性及上游参考等效。输出是 float32，有限浮点值超过满幅并不自动等于削波；整数导出或播放的电平策略另定，当前不暗中限幅、归一化或失真。

归一化和中间原率文件仅能放在该任务拥有的私有 staging 中，不进入最终双 stem 目录；预算包含源率解码副本、归一化副本、mmap 特征及两个输出与开销。探测、解码、归一化、worker、验证共用既定累计 deadline，排队等待不计；取消/超时/失败先停止并回收进程，再清理身份可确认的本任务资源。失败无法确认时保留 owner、隔离并返回 `CLEANUP_FAILED`，不得发布部分结果。目标已有对象、源变化、不支持媒体、缺/坏依赖和模型均须结构化错误、不覆盖源或目标；已接收后失败的 job 不可误报成功，预检拒绝不创建 ghost job。保持原有 C ABI、旧请求及默认禁用行为；已有结果 `frames` 继续表示输出规范化帧数，不因原始采样率改变语义。仅转换路径可在结果增补 `normalization` 对象，字段为 `source_sample_rate`、`source_channels`、`decoded_source_frames`、`tail_adjustment_frames`；最后一项是目标帧数减修正前输出帧数，正值表示尾部补零，负值表示尾部裁剪。原直接 float WAV 路径不依赖该可选字段，旧字段不变。变更实现后需合同、失败、实际进程、完整解码/帧数/声道与回归测试和独立复审；产品能力开关不因本节自动开启。
