# ADR-0008：macOS首版产品范围与验收冻结

- 日期：2026-11-10（工作始于11月9日）；状态：Accepted（Integration产品范围决策；独立规格审查见PROD-002报告）。
- 任务：PROD-002；基线main `eb020f44798d811284dc518a8caaa814a9def6ca` 已推送Codeup。

## 决定及边界

按[ADR-0007](0007-macos-first-delivery-order.md)先完成macOS。冻结产品范围、27组验收与结构化清单：20项MUST、2项CONDITIONAL、5项DEFERRED，覆盖首版剪辑、转码/批处理、AI分离、原生工作区/权限/键盘、最近任务、安全输出、开发包与独立QA。选有限、可证明的MP4/MOV H.264/AAC和常用音频子集，不追求参考软件的全部格式/功能。已有UI-001受限闭环不满足这些新必选项。

当前arm64/macOS27.0.1作为已记录的接收基准，Intel/旧OS后续。**不改变现有部署target、不引入新的产品最低OS或SDK要求，不声称这些目标已通过新功能验收。** 源码八函数ABI、schema、错误码、Cargo.lock和第三方依赖本轮不变。

P01/P02输出目标、软件编码参考、队列/素材/历史上限、显式精确模式与帧/音画/颜色判据、CPU两输出与模型候选均是产品要求，不是可直接传给当前Core的消息。旧Core的流/帧/媒体范围与30秒默认/300秒上限继续有效，拟议按操作期限不能越过现有校验。所有扩展先Integration/Core契约审定，平台不可自行添加私有FFmpeg/任务语义。

## 候选取舍与未接纳项

- 继续只做基础界面会留下转码/AI、批处理与安全/开发包缺口，因此不把UI-001当作“macOS做完”。
- 不一次支持所有格式/Intel/GPU/模型：缺设备、许可及端到端证据会造成不可验证承诺；保留有理由的条件/后续范围和诚实拒绝。
- 模型MC01评估对象为Demucs4.0.1/htdemucs指定checkpoint，人声+其余源合并两输出、CPU。代码MIT已查阅，但权重独立权利、完整SHA-256、不可变源码commit和runtime锁仍PENDING；本轮不下载、不安装、不接纳。AI-001未解决不得显示available，也不得接收macOS完成。
- 外部FFmpeg7.1.1/libx264仅软件参考候选，本机既有GPL运行时不随包；具体构建/编码器/许可需CORE-003/004和MAC-005审定。候选不是新增依赖批准，CLI隔离不是许可豁免。

## 成功、失败和变更控制

成功路径：用户选已支持媒体→Core返回真实能力→明确快速或精确→新目标预检/队列→执行/验证→安全提交→可定位/试听结果，独立证据接收后才开放完成声明。

失败1：源=目标/既有结果/已知批内非法项→预检整批拒绝无ghost，源和已有结果不变；预检后才变化的项可异步失败，其余继续。失败2：模型hash/许可或运行时不合格→拒绝加载，无隐式下载；AI必选仍BLOCKED。失败3：取消/写满/第二stem失败→资源及staging清理确认，无法确认则错误并保留owner，不能发布半套结果或假取消。

规格冲突须暂停相关实现并由Integration修订，记录变更原因、受影响F/AC/任务、版本与兼容/许可影响；不在失败后放宽断言来宣布完成。若候选被许可或性能挡住，重审候选和规格，不撤掉AI必选项冒充完成。回滚只回退产品文档版本，不动既有Core/macOS/HOS证据，不自动恢复旧并行排期。
