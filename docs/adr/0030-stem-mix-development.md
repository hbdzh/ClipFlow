# ADR-0030：受控双 stem 混音导出

状态：Integration/Core 受控开发设计，核心实现正在核验；不等于产品发行接收。

## 背景与决定

音源分离页面已能通过原生播放器对两条 stem 以各 0.5 增益试听，静音/独奏只影响试听，不能生成混音成品。为保持三端一致的媒体业务语义，新增显式 Core 队列操作 `mix_stems`，固定混合两条相同时间基的 float32 WAV，冻结可听轨，输出独立 float32 WAV。公共请求、拒绝条件及清理要求见 [开发契约](../../contracts/CORE-MIX-STEMS.md)。原生客户端只负责提供授权、选择、展示和持有作用域；Core 负责校验、任务、取消、最终发布和错误语义。

保留既有 C ABI 与旧消息；新能力在未明确启用或未探测成功时不可用，旧 Core 应拒绝新 operation，不能静默降级。输出不做归一化、限幅或重采样；浮点数据可超过满幅，播放和后续整数转换可能失真。对比直接在平台播放器内离线导出，此方案允许共享队列、安全文件事务和可检验语义，但每个平台仍需各自验证授权和本机媒体执行。

## 依赖、风险和回滚

本决策不授权新增模型、第三方依赖、SDK 最低版本或分发渠道。必须验证输入与输出真实格式、帧数和样本值，拒绝不同步文件；身份变化、覆盖竞争、进程回收或清理不确定时不得宣称成功。浮点幅度、长素材的资源上限和真实沙盒执行需实测；单台 macOS 不证明其他平台可用。回滚通过关闭显式能力并保留旧 AI 分离和试听流程完成，不能通过丢弃新字段自动重试。

## 验收状态

此文件记录设计与兼容边界。实际证据以各测试结果为准，不能由文件本身推导通过。当前代码静态审查显示发布和取消使用同一互斥锁，发布完成后以共享标志阻止取消误改状态。受控本机测试覆盖了真实编码写入期间取消及成功后取消；发布与终态更新之间的精确竞争窗口未动态覆盖。无法确认子进程回收时需保留私有暂存及资源预约并隔离，异常回收的故障注入证据未取得。用户目录中的同 UID 恶意并发路径替换不在已证明的安全范围内。平台 GUI/沙盒及长素材等验证应分别记录实际证据；未执行项保留。
