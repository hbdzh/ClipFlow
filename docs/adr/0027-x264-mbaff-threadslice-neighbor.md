# ADR-0027：MBAFF 扫描方式判断的线程切片边界

2026-11-16，Proposed。仅本机 macOS arm64 受控构建；由独立 Integration 审准具体补丁/配方与实际验收后采纳，不批准发行。旧 v5 与 154 份封版证据保持。

| --- | --- |

## 问题与最小决定

`x264_field_vsad` 在选择 MBAFF 的 field/frame 扫描时，用上方宏块的 field 标志作偏置。原判断只有 `mb_y > 0`；线程切片首行的上方宏块由另一个工作线程写入，当前线程开始判断时没有完成屏障。相邻缓存装载已经明确不能从上一 threadslice 预测，该偏置却越过同一边界。

候选修复只把上方偏置的可用条件改为 `mb_y > h->i_threadslice_start`。线程内部由本线程顺序完成的上方行继续可用；切片首行跳过不可用的上邻居。普通非切片的起点为 0，保持原逻辑。左邻居已由本线程顺序完成，不改其条件。

另在宏块邻居缓存准备中跳过首个 MBAFF pair 的上方位置调整：原先会先读前切片 field，之后又被邻居可用性判断丢弃。此调整只影响被丢弃的局部 top 坐标，保留左侧处理；单独静态审查和组合对照，不把它冒认为像素差异的原因。先运行仅 pixel 条件的因果配方，再验证加入这处死读保护的组合码流相同。

不采用关闭 MB-tree、减少线程、改变扫描参数、整帧串行、任意清零共享状态或放宽重复性预期的办法。不在未经证明的 hpel/MBAFF 过滤范围加入额外全局屏障。该修复是正常编码确定性/并发读取边界修补，不映射成 CVE 漏洞复现或完整 CVE 修复。

## 失败边界与验证

静态成功例：非切片 start=0 与原逻辑一致；本切片第二个及以后 MB pair 读取已由本线程完成的上方状态。失败例：当前切片首行即使全帧 y>0，上方也不可用；前切片稍快或稍慢不能影响当前扫描决定。片中额外 NAL slice 切分仍保留本工作线程已经完成的邻居。

先对既有合法输出解码，记录差异 frame/plane/row 与 slice 的对应，不新增恶意媒体。补丁审准后从同一原归档和前置补丁分别构建旧/新 raw-only CLI，同编译器/SDK/布局/参数；旧差异保留，新要求编码与完整解码及逐帧哈希完全重复。覆盖原 10 位 TFF 场景、BFF、8/10 位、420/444、不同片数及非均分片高；逐行与非切片控制要求旧/新码流相同。未实测的组合明确保留，不声称全配置确定性。

新 v6 从配对完整静态库重新链接，锁原归档、五补丁次序、11 源及许可材料，独立审后构建，不覆盖旧包。执行变更相关正常回归、原生资源协议、静音 GUI 导出与输出解码；参数、黄金与门槛不变。只生成自有测试文件，不播放、启用旁白或访问音频设备。没有漏洞样本/复现、故障注入或外发消息。

## 回滚与保留

回滚使用封存 v5，不能改写其隔行失败结论。活动 OpenCL 回调退出/驱动错误、caller callback 转移与计数、临时文件独占身份、分配失败 STATIC_ONLY、CNA 版本与 AAC/RCE 映射继续独立保留。完整 QA-002、其他平台与公开发行不随本机有限修复接收；公开发行 NO_GO。
