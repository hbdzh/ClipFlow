# ADR-0015：不依赖 Python 的原生音源分离 worker（草案）

日期：2026-11-13。状态：**受控开发实现及定向验证；发行未接收**。用户要求软件运行时不依赖 Python。Integration 已复核原生配置、旧 JSON/C ABI 兼容边界和候选依赖；实际证据见 MAC-004 QA。

## 目标与边界

用户安装和实际分离不依赖系统或应用内的 Python。Rust Core 继续负责共享任务队列、格式规范化、取消、资源与双输出事务；原生独立 worker 负责固定模型的频谱处理、推理及重建，通过明确版本的运行时加载方式使用 ONNX Runtime。模型、运行时和 FFmpeg 的具体构建、签名及许可另行确定，不暗示它们无需随应用提供。开发或对照工具使用 Python 与产品运行时依赖分开。

## 与现有实现的兼容

历史 `ai_backend` 使用 `python`、`worker`、`model`，Core 以 `python -I` 启动并校验固定脚本哈希。现新增原生配置，与旧字段互斥并保持旧配置及八函数 ABI；MAC-004 使用新配置，旧的 Python 组件书签不会自动当作原生组件。相关字段及失败行为见 Integration/Core 复核的 [AI-001 契约](../../contracts/AI-001.md)。

原生 worker 仍由 Core 隔离启动，沿用参数数组、进程组、超时、取消、受控 staging、固定输出和结果核验。实际交付的可执行文件、动态库和模型须有可核对的身份与来源；源码哈希不能替代最终二进制身份。直接继承用户环境或自动下载不作为方案前提。

## 算法一致性

现有 worker 不仅调用模型：它做 4096 点 STFT、中心反射填充、1024 hop、状态化双向 LSTM 的逐层分块以及逆变换和残差伴奏。按固定长度独立运行原 ONNX 图会改变双向上下文，不能作为等价替换。可行候选是离线生成并固定可复现的前后处理及六个方向性 LSTM 子图，绑定原模型和各子图哈希；worker 以相同顺序传递状态并保持现有有界磁盘/内存处理。子图生成、权利链及输出一致性均需独立验证，方案尚未定稿。

## 本机定向实验

macOS arm64，Rust 1.99.0，固定原模型 SHA-256 `f27742bb52b24cb039614dc76d0764e279df3eb2a9d6daa82c6daee3369ec747`，临时开发环境的 ONNX Runtime 1.22.1 dylib SHA-256 `7dfd3b3116d02d984d516c741c01453ec22d7cfd36e16242626579d4f5bbdc80`。仅在 `/private/tmp/mediastudio-rust-ort-spike` 建立一次性 Rust 验证程序，输入八帧全零频谱，不是音频分离或质量验收。

- `ort = 2.0.0-rc.10`、动态加载本机 dylib：模型返回 `1×2×2049×8` 共 32784 个有限值，但进程退出时因 C++ `mutex lock failed: Invalid argument` 异常中止，退出码 134；工具沙盒和宿主直接运行均复现。**失败，不可用于产品。**
- `ort = 2.0.0-rc.15`、`api-22`、相同 dylib：构建通过，执行时段错误，退出码 139，未取得推理结果；具体原因未定位。**失败，不可用于产品。** 上游说明 rc.15 修复了多项内存安全问题，不能因旧版能计算就直接采用旧版。参见 [ort 发布记录](https://github.com/pykeio/ort/releases/tag/v2.0.0-rc.15)。

后续分析崩溃栈发现 rc.15 在启用 `api-22` 时默认选择自动设备策略，进入 ORT 的 NPU 选择路径；关闭该 feature 并使用 `api-21` 后，同一模型可推理并正常退出。现原生 worker 锁定 `ort` 2.0.0-rc.15、`api-21`，使用本机 ORT 1.22.1 CPU 测试。旧版退出崩溃发生在 ONNX Runtime 环境析构，具体机制未定位；不可因为拿到输出就算通过。wheel 内 dylib 仍不代表已经审定的分发物。

新 worker 在真实 3 秒及跨分块的 8 秒授权音频上与旧实现对照，并经 Core、Swift 和 ad-hoc 沙盒包做定向验证，详见 QA。原生组件配置与旧 JSON 互斥，C ABI 不变；公开 Rust `AiBackendConfig` 字段调整会破坏直接使用旧字段的外部 Rust 源码。新依赖的锁文件和直接声明见 [worker README](../../core/native-ai-worker/README.md)，Integration 对 33 个 crate 的本地许可元数据初查未见 GPL 声明；实际二进制、完整传递依赖/NOTICE 和渠道义务尚未完成发行审查。正式签名、10 分钟资源峰值和其他平台未验证。

## 后续必要工作

1. 确定来源可复现、版本锁定的最终 ONNX Runtime 与 Rust 绑定，核对实际传递依赖及许可证；当前组合仅为受控开发材料。
2. 补充目标发行物身份、模型和子图获取与升级方案，以及正式签名和许可材料。
3. 按产品需要验证原生长音频资源、沙盒取消和异常清理、其他平台与主观听感；已有定向结果不覆盖上述场景。
4. 完成可安装开发包和发行渠道验收；当前临时 ad-hoc 沙盒包不等于正式交付。
