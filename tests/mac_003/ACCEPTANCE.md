# MAC-003 独立验收条件

先冻结此预期，再运行生产客户端。新测试不得修改旧 MAC-002 / CORE-004 预期。

| 项目 | 必须观察到的事实 |
|---|---|
| P01/P02 与音轨 | 实际批次导出；横竖 P02 分别 1280×720 / 720×1280；P01 保持受支持尺寸；all、none 与全局 stream index=2 单轨选择均符合实际 ffprobe、全段解码与生成音调身份。 |
| 草稿身份 | 批接收后切素材并改范围/预设/音轨，不改变已接收任务；一个共享 Core session，任务本地 UUID 与 Core ID 一一对应。 |
| 原子拒绝 | 一项目标存在时整批拒绝，无幽灵任务、无半批输出，原目标内容不变；错误对应失败项目。 |
| 排序/取消 | 真实 Core queued IDs 重排回执与客户端显示一致；运行中和等待中取消最终 cancelled，输出和暂存清理；不能用本地假队列代替。 |
| 逐项失败/重试 | 后端实际子进程故障使一项失败，其他项独立成功/取消；失败与取消可通过 Core 重试到新目标，产生新本地/原生 ID；旧记录不改写；相同或已存在目标拒绝。 |
| 生命周期 | FFI 全部非主线程，输出调用与 exact buffer free 一致，MainActor 心跳持续；shutdown 后句柄确认关闭且授权 lease 配对。 |
| 宿主容量 | 同一原生 queue engine 实际接受 32 条有界任务，第 33 条拒绝且无新任务；全批取消后 32 项均终态、输出不存在、lease 归零。此项不等于 32×10 分钟满负载。 |
| 提交中交互 | 真实 ffprobe 预检被短暂 gate 时，取消旧项不取消新批；取消新 pending 批保持原 token 至回执后按真实 ID 取消；关闭等待提交返回后清理。first-connect 与 before-connect/before-submit 两实际调用边界关闭后不出现新作业或悬空访问。 |
| 恢复 | 重启只恢复有界元数据和书签，不自动重跑，不把旧 engine job ID 当活句柄；清历史同时反映 Core 与本机摘要。 |

媒体验证独立读取文件，不导入生产 validator。全部样本由 lavfi 色图/正弦音生成，媒体、工具包装器、运行日志仅保存在忽略的 `build/`。包装器只对真实编码调用延迟/故障一次，其他请求 exec 本机 FFmpeg；不伪造 Core 状态或成功媒体。

GUI 原生按钮/面板交互由 Integration 单独记录；CLI scenario 与真实 GUI 不是同一证据。App Sandbox、签名、公证、Intel、后两端、极限压力和完整主观保真未执行时保留 NOT_RUN。
